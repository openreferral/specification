How to use the HSDS Profile Wizard to Generate and Maintain a HSDS Profile
==========================================================================

The HSDS Profile Wizard is a CLI tool to help you develop and maintain your HSDS Profile schemas according to the [HSDS Profiles Specification](https://docs.openreferral.org/en/latest/hsds/profiles.html).

It handles generating full Profile schemas from your Profile patches, including best practices such as generating `$id` properties for your schemas.

It is a standalone tool which integrates into your Profile project. It doesn't replace other tools i.e. version control but can be used to automate the tasks required to generate and maintain a HSDS Profile.

This documentation is intended to demonstrate how to install and use the HSDS Profile Wizard and assumes some knowledge of HSDS Profiles. For more information and guidance on HSDS Profiles, please consult [our guidance on creating profiles](./creating-profiles).

## Installing the HSDS Profile Wizard on your system

To install the HSDS Profile Wizard you will need a Python environment on your system, with a package manager such as `pip` or  `pipx`.

You can find excellent resources on getting started with installing Python and its package managers on the Python website:

* [Python For Beginners](https://www.python.org/about/gettingstarted/) 

Once you're set up with Python and a compatible package manager, the fastest way to install the HSDS Profile Wizard is to install it system-wide on your computer with `pipx`.

```bash
pipx install git+https://github.com/openreferral/hsds-profile-wizard@main
```

You may prefer to install the HSDS Profile Wizard into a Python virtual environment. Instructions to do this can be found in the README file of the HSDS Profile Wizard on Github:

* [HSDS Profile Wizard (Github)](https://github.com/openreferral/hsds-profile-wizard)

Check that you have the HSDS Profile Wizard installed correctly by running `hsds-profile-wizard` in a terminal. It should output something like the following:

```
Usage: hsds-profile-wizard [OPTIONS] COMMAND [ARGS]...

  HSDS Profile Wizard

Options:
  --help  Show this message and exit.

Commands:
  generate   Generates and compiles Profile Schemas based on HSDS Schemas...
  gitignore  Outputs some content to STDOUT which you can append to a...
  init       Initialise a new Profile
```

## Setting up your Profile project directory

If you haven't done so already, create a new empty directory for your Profile. Going forward, this tutorial assumes all commands are run inside of the directory for your new profile.

Next, run `hsds-profile-wizard init`. This command walks you through a short wizard which prompts you for some details for the Profile. Everything you enter can be changed later. It asks you for the title of your Profile e.g. "My Example Profile", and the base URL of your profile. The base URL is important because it will be used to generate identifiers for your schema files.


```{admonition} Choosing a good base URL
The base URL for your Profile should result in URLs which are publicly accessible and resolvable to your schemas. The HSDS Profile Wizard uses your base URL to generate the following:

* `$id` values inside of schemas, which uniquely identify schemas and should be resolvable
* `$ref` values inside of `openapi.json`, which link API endpoints to your schemas.

For example, if you give a base URL of `https://example.com`, then the `$id` property of `service.json` will be set to `https://example.com/0.0/service.json`. This URL should be resolvable to the 0.0 version of your `service.json` schema, to allow humans and machines to retrieve the schemas. If you are using a popular source control system such as Github, SourceHut or Codeberg to manage your Profile schemas, you can simply use the URL of the repository. The HSDS Profile Wizard will automatically handle converting these urls into ones which return the actual file.
```

After responding to the prompts, the HSDS Profile Wizard will generate some files and directories for you:

* The `profile.json` file contains the settings of your Profile. If you want to change anything like the base URL or the title, then you can do it here (among other things).
* The `profile/` directory is where you will write the changes to HSDS which comprise your Profile.
* The `schema/` directory is the output directory, where your final patched schemas will be generated by HSDS Profile Wizard.

## Implementing your Profile in the `profile/` directory

Now you can begin implementing your Profile in the `profile/` directory. You can do this by creating JSON Schema files to modify HSDS' schemas or create your own.

Files with the same name as a schema in HSDS (e.g. `service.json`) will be applied as patches to the corresponding HSDS schema (see [RFC 7396](https://www.rfc-editor.org/rfc/rfc7396)). Files with different names will be treated as your own new schema files.

The HSDS Profile Wizard will place the final results inside the `schema/` directory. It is these files which make up your Profile.

If you need guidance on how to achieve specific effects in your Profile such as adding/removing fields or API endpoints, please see our [HSDS Profile Cookbook](./hsds-profile-cookbook) for details.

## Generating your profile schemas

When you're finished implementing your Profile inside `profile/`, you are ready to generate your final Profile schemas.

Run `hsds-profile-wizard generate` to generate your Profile schemas inside of the `schema/` directory. The HSDS Profile Wizard will automatically pull down the latest copy of the HSDS schemas and then apply your Profile's patches inside of `profile/` where appropriate. It will also copy any new schemas you've added to the `schema/` directory.

By default, the HSDS Profile Wizard will use the latest version of HSDS as defined by the default branch on the canonical [HSDS Github repository](https://github.com/openreferral/specification/.). If you prefer, you can change this with the `--branch` flag to specify a version of HSDS to base your Profile on.

For example to explicitly base your Profile on HSDS 3.1, you would use the following command:

```
hsds-profile-wizard generate --branch "3.1"
```

## Some common errors and how to handle them

When generating your Profile with HSDS Wizard for the first time, it is likely that you will encounter some errors. This is normal, and errors usually represent some extra tweaking that you need to do.

The HSDS Profile Wizard tries to give helpful error messages and suggestions of how to fix them. This section exists to give examples of fixing these errors for extra guidance.

### Error when generating openapi.json file: path references schema which does not appear in your Profile

Example of error:

```
Error when generating openapi.json file: path /service_at_locations/{id} references schema 'service_at_location.json' which does not appear in your Profile. Consider patching this path via profile/openapi.json`
```

This error occurs because the HSDS Profile Wizard has spotted that your Profile's `openapi.json` file contains a path which returns a schema that doesn't exist in your Profile.

The HSDS Profile Wizard is attempting to generate your Profile's `openapi.json` file by updating the URLs referencing schemas in the base HSDS `openapi.json` file, but when it comes to this path (`/service_at_locations/{id}`) it has spotted that the `$ref` value points to a schema which doesn't exist in your Profile.

This usually happens because there isn't a patch to the `openapi.json` file in your Profile which updates this.

If you haven't done so already, create `profile/openapi.json` and either:

* Update the `$ref` value of the return schema, if you want to keep the endpoint
* Remove the path entirely if you no longer need this endpoint in your API specification

This example removes both the`service_at_locations/{id}` and `service_at_locations` paths entirely from the `openapi.json` file:

```json
{
  "paths": {
    "/service_at_locations/{id}": null,
    "/service_at_locations": null
  }
}
```

## Maintaining your Profile with HSDS Profile Wizard

Congratulations! You've just generated your first HSDS Profile. 

Now, you should fill out the `description` and `docs_url` fields inside of `profile.json` to provide a brief description of your Profile and to link people to documentation.

You should follow the guidance in Creating Profiles on how to maintain and version your Profile. When you're ready, you can update your Profile using the HSDS Profile Wizard.

When updating the version of your Profile, update the `version` property inside of `profile.json` whenever you release a new version. This keeps all of the `$id` identifiers for your Profile schemas unique and resolvable, which helps tools such as validators identify and cache schemas to save on network bandwidth.

Integrating changes from upstream HSDS is as simple as re-running `hsds-profile-wizard generate` to rebase your Profile off of a new version of HSDS.

It's also simple to "pin" your Profile to a specific HSDS version. Use the `--branch` flag when running  `generate` to ensure that you only use features from that version of HSDS.
